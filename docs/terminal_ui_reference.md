# Terminal UI Reference Style

## الهدف

تجعل واجهة Nabdcode الطرفية التنفيذ قابلاً للمسح البصري على شاشة الهاتف، على نمط الواجهة المرجعية: تسلسل واضح للقراءة والتعديل والتشغيل، مخرجات مختصرة قابلة للتوسيع، ومؤشر صريح لسير عمل الخطة والتنفيذ.

## مكونات العرض

| المكوّن | السلوك |
|---|---|
| شارات الأدوات | تعرض `READ` و`EDIT` و`SHELL` و`TODOS` و`TASK` حسب الأداة والفعل الحقيقي، لا حسب اسم تقني مجرد. |
| رؤوس الأدوات | تعرض المسار أو الأمر أو الاستعلام؛ وتعرض تفويض `TASK` الدور والعقدة المختارة عند وجودها. |
| نتائج الأدوات | تُختصر المخرجات الطويلة وتُحفظ للاسترجاع عبر `Ctrl+O`. |
| بطاقات diff | تعرض عدد الإضافات والحذف ومعاينة ملونة محكومة بعدد أسطر. |
| التفكير | يظهر زمن النشاط فقط بصيغة قابلة للطي؛ لا يطبع محتوى الاستدلال أو التخطيط الداخلي. |
| شريحة الحالة | تستخدم فعلًا مرحليًا مثل `Examining` أو `Sculpting` أو `Verifying` من دون اختلاق عداد tokens. |
| الموجّه | يعرض الوضع الفعلي: normal أو PLAN أو APPLY، ويضيف ملخص Task Graph عند وجوده. |

## حدود الأمان

> العرض لا يملك سلطة تنفيذ. كل الشارات والمؤشرات والملخصات قراءة فقط ولا تغير `RuntimeState` أو عقد Task Graph أو سجلات التدقيق.

يبدّل `Shift+Tab` بين normal وPLAN عبر دالة Plan/Apply الفعلية، ويحدّث تعليمات السياق. عندما يكون APPLY مفوضًا، لا يستطيع الاختصار إلغاء التفويض أو الرجوع للوضع العادي؛ يظل الانتقال محكومًا بأوامر سير العمل الصريحة. تُعقّم النصوص المعروضة قبل المرور إلى الطرفية أو إلى HTML الخاص بالموجه.

## Task Graph والتفويض

تعرض بطاقة `TASK` الدور والعقدة وحالة الأدلة المستخرجة من `ToolResult.metadata`، بدل عرض JSON الخام. ويضيف الموجه ملخص الرسم الذي يتضمن الإصدار والوضع والعقدة النشطة والعقد الجاهزة والحالات والأدلة. لا يكشف ذلك محتوى الاستدلال أو بيانات اعتماد أو معلمات الحالة الداخلية.
